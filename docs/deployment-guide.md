## 1. System requirements

| Requirement | Minimum |
|---|---|
| Operating system | Windows 10/11, Linux, or macOS supported by Docker Desktop/Engine |
| Docker Engine | Docker Engine 24+ |
| Docker Compose | Compose v2 |
| Memory | 2 GB available |
| Free disk | 2 GB for images and the PostgreSQL volume |
| Host port | TCP 8000 must be available |

The application image uses Node.js 20 Alpine. The database image uses PostgreSQL 16 Alpine. PostgreSQL is reachable only from the Compose network; it is not published on a host port.

## 2. Start and stop

From the repository root, start the prototype with one command:

```powershell
docker compose up -d --build
```

Compose waits for PostgreSQL's health check before starting the API. Schema and sample records are loaded automatically on the first database-volume initialization. The container generates an ephemeral JWT secret if none is provided; tokens become invalid when the application container is recreated.

Stop the services without deleting database records:

```powershell
docker compose down
```

To deliberately reset the local sample database, remove the volume:

```powershell
docker compose down -v
```

The Compose database credential is for this local demonstration only. Do not expose the database or reuse the credential outside this local prototype.

## 3. Environment variables

| Variable | Meaning | Compose value/default | Required |
|---|---|---|---|
| `PORT` | HTTP port inside the API container | `3000` | Yes |
| `NODE_ENV` | Runtime mode | `production` | Yes |
| `STORAGE_DRIVER` | Persistence implementation | `postgres` | Yes |
| `DATABASE_URL` | PostgreSQL connection URI | Internal Compose service `postgres`, database `mekong_crm` | Yes |
| `DATABASE_SSL` | Enable TLS for PostgreSQL | `false` on the local Compose network | No |
| `DATABASE_POOL_SIZE` | Maximum PostgreSQL pool size | `10` in application configuration | No |
| `JWT_SECRET` | JWT signing secret | Randomly generated by the container entrypoint when absent | No for Compose; required for a direct local run |
| `BUSINESS_TIMEZONE_OFFSET_MINUTES` | SLA timezone offset | `420` (UTC+7) | No |
| `BUSINESS_START_HOUR` | Start of a workday | `8` | No |
| `BUSINESS_END_HOUR` | End of a workday | `17` | No |
| `BUSINESS_WORKING_DAYS` | Working weekdays (`1`=Mon, `6`=Sat) | `1,2,3,4,5,6` | No |
| `BUSINESS_HOLIDAYS` | Comma-separated excluded dates (`YYYY-MM-DD`) | Empty | No |

For a direct Node.js run, create `src/.env` from `src/.env.example`, set `STORAGE_DRIVER=memory` or configure PostgreSQL, and replace the example `JWT_SECRET` with a unique random value of at least 32 characters.

## 4. Sample data and verification counts

PostgreSQL runs `src/db/schema.sql` and `src/db/seed.sql` automatically when the named volume is initialized for the first time.

Expected baseline after a fresh initialization:

- 1 customer
- 1 device
- 2 technicians
- 3 user accounts (`frontdesk`, `manager`, `technician`)
- 1 ticket


## 5. Verify the system

Check container health:

```powershell
docker compose ps
```

Both `postgres` and `app` should report `healthy`.

Check the API:

```powershell
Invoke-RestMethod http://localhost:8000/health
```

Expected JSON has `status: "healthy"`, a numeric `uptime`, and an ISO-8601 `timestamp`.

Run the automated suite inside the API container:

```powershell
docker compose exec -e TEST_DATABASE_URL=postgres://postgres:postgres_secure_pwd@postgres:5432/mekong_crm app npm test
```

Expected result is 19 tests passed and zero skipped for the current suite. The PostgreSQL integration test is skipped if `TEST_DATABASE_URL` is omitted. On a host installation with Node.js 20+, install dependencies using `npm ci` and run `npm test`.
